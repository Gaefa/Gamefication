# Internationalization Plan

## 1. Supported Languages

Base game must support:
- English (`en`);
- Russian (`ru`).

English is the source language for keys. Russian is required for every player-facing text before public builds.

## 2. Runtime Layer

Godot autoload:
- `Localization`;
- file: `res://scripts/autoload/localization.gd`;
- strings: `res://content/base/localization.json`.

Usage:
- UI code calls `Localization.t("key", "Fallback")`;
- never add new permanent UI strings without a localization key;
- temporary debug-only strings are allowed only if not player-facing.

## 3. Content Rule

For content JSON, future migration should move visible fields to localization keys:
- `label_key`;
- `description_key`;
- `title_key`;
- `body_key`.

Current content still has direct English labels. This is acceptable only during prototype phase. Before demo, content must be migrated or mirrored into localization keys.

## 4. UI Rule

New UI panels must:
- use `Localization.t`;
- rebuild visible text on `Localization.locale_changed`;
- avoid concatenating grammar-sensitive phrases when possible.

Acceptable:
```gdscript
label.text = Localization.t("ui.governance.title", "Governance")
```

Avoid long-term:
```gdscript
label.text = "Cost: " + cost_text
```

## 5. Current Coverage

- English/Russian localization JSON;

- top resource/risk bar labels;
- build panel static labels and category tabs;
- info/help panel static text;
- building flow diagnostics;
- event popup fallback buttons and cost labels;
- Governance UI localized as first working example.
