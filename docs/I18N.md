# Internationalization Plan

## 1. Supported Languages

Base game must support:
- English (`en`);
- Russian (`ru`).

English is the source language for keys. Russian is required for every player-facing text before public builds.

## 2. Runtime Layer

Godot autoload:
- `Localization`;
- file: `res://scripts/autoload/localization.gd`;
- strings: `res://content/base/localization.json`.

Usage:
- UI code calls `Localization.t("key", "Fallback")`;
- never add new permanent UI strings without a localization key;
- temporary debug-only strings are allowed only if not player-facing.

## 3. Content Rule

For content JSON, visible fields must have localization keys:
- `label_key`;
- `description_key`;
- `title_key`;
- `body_key`.
- `name_key`;
- `stage_key`;
- `text_key`;
- `accept_label_key`;
- `decline_label_key`;
- `message_key`.

Direct English fields remain as fallback/source text. Runtime UI should read them through `Localization.content_text(def, field, fallback)`, not through `def.get("label")` directly.

## 4. UI Rule

New UI panels must:
- use `Localization.t`;
- rebuild visible text on `Localization.locale_changed`;
- avoid concatenating grammar-sensitive phrases when possible.

Acceptable:
```gdscript
label.text = Localization.t("ui.governance.title", "Governance")
```

Avoid long-term:
```gdscript
label.text = "Cost: " + cost_text
```
