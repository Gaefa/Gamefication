# v0.2 Early Access Sprint Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** довести проект до v0.2, которую можно дать внешним тестерам как Early Access candidate: 30-45 минут понятного citybuilder-геймплея с победой/поражением, диагностикой причин и стабильным Windows build.

**Architecture:** v0.2 не добавляет новые большие системы ради количества. Основной упор: завершить причинно-следственную цепочку `resource -> logistics -> utility -> demand -> pressure -> scenario`, чтобы игрок понимал, почему город растет или ломается. Все новые правила должны идти через data/content, core systems и диагностику, а не через разрозненные UI if-statements.

**Tech Stack:** Godot 4.6, GDScript, content JSON, fixed simulation tick, headless Godot verification, Steam-first release flow.

---

## 1. Release Positioning

v0.2 не должна быть финальным Steam Early Access launch. Это `EA Candidate / Closed Playtest Build`.

Цель v0.2:
- собрать одну честную playable vertical slice;
- дать 5-10 людям без созвона;
- получить данные: где игрок не понимает UI, где ломается баланс, где скучно;
- после этого принять решение: v0.3 как Steam Demo или сразу подготовка Steam Early Access.

Публичный Early Access допустим только после v0.2 playtest, если:
- 70% тестеров понимают следующую цель без объяснения;
- 70% тестеров понимают причину провала/дефицита;
- нет blocker bugs в save/load/build/export;
- первый сценарий можно пройти минимум 2 разными стратегиями.

## 2. v0.2 Scope

### Must Have

- Road logistics v1 for physical resources.
- Distance/throughput penalty for road-delivered resources.
- Water utility v1: local underground coverage + water reserve storage.
- Power utility v1: local underground coverage + energy/battery buffer.
- Citizen demands v1 for levels 1-4.
- Scenario `Found A Stable Town`.
- Objective/mandate panel.
- Pressure director tuned for first 30-45 minutes.
- 8-10 readable events/crises.
- Map generation with safe start zone.
- Building sprites for core early buildings, fallback for the rest.
- Balance pass for city levels 1-4.
- Save/load smoke test.
- Windows export preset and build checklist.

### Should Have

- Logistics overlay by road component.
- Water/power overlay as underground service coverage.
- First-time tutorial hints tied to actual player state.
- Main menu polish pass.
- RU/EN localization check for all v0.2 UI text.

### Won't Have In v0.2

- Mobile UI.
- DLC hooks visible to players.
- Regional cluster mode.
- Multiple factions/patron switching.
- Full ideology/religion layer.
- Rail/metro.
- Procedural campaign.
- Full Steam store assets.

## 3. Definition Of Done

v0.2 is done when:

- Fresh player can start a new game and see a clear first objective.
- Player can build road, housing, food, wood, stone, warehouse, water, power and upgrade at least one building chain.
- Physical resources require road logistics.
- Distance from supplier/storage has visible gameplay impact.
- Water/power are shown as utilities, not confused with ordinary resource stockpiles.
- City can reach level 4 without console/debug actions.
- Scenario can be won or failed.
- Events target valid unique buildings and explain consequences.
- UI explains at least these failure states:
  - no road delivery;
  - stockpile empty;
  - water not covered;
  - power not covered;
  - cap/storage blocked;
  - pressure rising;
  - unmet citizen demand.
- `npm run check` passes.
- Godot headless launch passes.
- Manual 30-minute playthrough has no blocker bug.

## 4. Sprint Cadence

Recommended cadence: 4 focused sprints, 1 week each.

### Sprint 1: Logistics And Utilities

Goal: make resources mechanically honest.

Deliverables:
- `RoadResourceNetwork` or equivalent extension of `ResourceFlow`.
- Road components for physical resources.
- Distance-to-supplier/storage calculation.
- Delivery efficiency based on distance and road tier.
- Warehouse as logistics hub, not only cap extender.
- Water/power moved toward explicit utility status.
- HUD/building diagnostics updated for delivery vs stock vs utility.

Exit criteria:
- A building with road access but no connected supplier/storage cannot magically consume distant resources.
- A far building runs worse than a near building.
- A warehouse improves local delivery.
- Diagnostics say why.

### Sprint 2: Scenario, Citizen Demands, Objectives

Goal: create a real playable loop with a finish line.

Deliverables:
- `scenarios.json`.
- `ScenarioSystem`.
- Scenario `Found A Stable Town`.
- Objective panel in HUD.
- Citizen demands v1 by city level.
- Mandate pressure/reward hooks for the scenario.

Exit criteria:
- New game starts with a scenario objective.
- Player can win or lose.
- Demand failures affect happiness/pressure in visible ways.

### Sprint 3: Events, Map Generation, Balance

Goal: make the first 30-45 minutes replayable and fair.

Deliverables:
- Guaranteed start zone.
- Resource/terrain clusters.
- 8-10 events tuned for early/mid game.
- Event targeting validates unique buildings.
- Balance pass for city levels 1-4.
- Storage/cap progression tuned around warehouse levels.

Exit criteria:
- First 10 minutes are never dead due to bad map RNG.
- Events create decisions, not random punishment.
- Level 4 is reachable without grinding for an unreasonable time.

### Sprint 4: UX, QA, Build

Goal: make v0.2 testable by people outside the project.

Deliverables:
- UI polish pass for HUD, help, objectives, city panel.
- RU/EN localization pass.
- Save/load smoke test.
- Windows export preset.
- Build naming: `v0.2.0-ea-candidate`.
- Playtest checklist.
- Known issues file.

Exit criteria:
- External tester can launch and play without live explanation.
- Build can be shared as zip.
- Tester feedback can be collected against clear questions.

## 7. Early Access Gate

Do not go public Early Access if any item is true:
- player needs Discord explanation to start;
- resource delivery reasons are unclear;
- scenario cannot be won/lost;
- map RNG can create unwinnable starts;
- save/load corrupts normal play;
- Windows export is not repeatable;
- UI still looks like debug tooling in core flow.

Public EA can start after v0.2 only if playtest data supports it. Otherwise v0.2 becomes closed playtest, v0.3 becomes Steam Demo candidate.
